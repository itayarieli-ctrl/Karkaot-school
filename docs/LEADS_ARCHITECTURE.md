# ארכיטקטורת הלידים — המדריך לחיבור דפים ל-Scalla

> **למי המסמך הזה:** לכל מי שיוסיף/יעדכן דף נחיתה בעתיד — המשתמש, Claude,
> או כל מפתח. הוא מסביר איך ליד עובר מהאתר ל-Scalla CRM, מה קבוע ומה זמני,
> ואיך לחבר **דף חדש** בלי לשבור כלום.
>
> עודכן: 2026-08 · נכתב אחרי שהחיבור ל-Scalla אומת בייצור.

---

## 1. התמונה בגדול — שלוש שכבות

ליד עובר שלוש תחנות. חשוב להבין מי אחראי על כל אחת:

```
   דף נחיתה              השרת שלנו                 Scalla CRM
  ┌─────────┐          ┌──────────────┐          ┌──────────────┐
  │ LeadForm │ ──POST─▶ │ /api/lead    │ ──POST─▶ │ Webform      │
  │ (טופס)   │  JSON    │ route.ts     │  form    │ capture.php  │
  └─────────┘          └──────────────┘          └──────────────┘
   קומפוננטה            נקודה אחת שמרכזת            הגדרות, שדות,
   לשימוש חוזר          את כל הלוגיקה               טריגרים, התראות
```

- **שכבה 1 — הטופס (`LeadForm`):** קומפוננטת React אחת, מקבלת פרופס. מוטמעת
  בכל דף בשורה אחת.
- **שכבה 2 — השרת (`/api/lead`):** נקודה אחת שמקבלת את כל הטפסים, מאמתת,
  ומעבירה ל-Scalla. **כאן חיה כל לוגיקת ה-Scalla — אין שכפול.**
- **שכבה 3 — Scalla:** הגדרות ה-CRM (שדות, מניעת כפילויות, טריגרים,
  התראות WhatsApp). **לא בשליטת הקוד** — מוגדר בממשק Scalla.

> **עיקרון מנחה:** כל מה שבשכבות 1–2 הוא קוד שלנו (עובר לכל מימוש עתידי בקוד).
> כל מה שבשכבה 3 עובר לכל מימוש — **גם אם ביום מן הימים יעברו לפלטפורמה אחרת**
> (Elementor, וכו'), כי טופס Scalla מוטמע בכל אתר. **ההשקעה הכי בטוחה לטווח
> ארוך היא בצד של Scalla.**

## 2. ⭐ איך מחברים דף חדש — 3 צעדים

### תרחיש א': דף חדש למוצר קיים (קורס או ייעוץ)
זה הרוב המוחלט של המקרים. **אפס שינוי בקוד השרת.**

1. בנה את הדף החדש (קומפוננטה / route).
2. הטמע את הטופס בשורה אחת, עם ה-`interest` המתאים:
   ```tsx
   // דף קורס חדש:
   <LeadForm data={myCopy} fixedInterest="course" id="lead" />

   // דף ייעוץ חדש:
   <LeadForm data={myCopy} fixedInterest="consult" id="lead" />
   ```
3. זהו. הדף יורש אוטומטית: חיבור ל-Scalla, שדה חותמת-הזמן, ההסכמה, הכל.

### תרחיש ב': מוצר חדש עם טופס Scalla חדש
(למשל "קורס מתקדם" עם צינור מכירה נפרד ב-Scalla.)

1. **ב-Scalla:** צור Webform חדש. רשום את ה-`publicid` ואת שם הטופס המדויק.
2. **בקוד** (`src/app/api/lead/route.ts`) — הוסף מפתח ל-`SCALLA_FORMS`:
   ```ts
   advanced: {
     publicId: "...",              // מ-Scalla
     formName: "שם הטופס המדויק",   // חייב להתאים אות באות
     consentFieldId: "cf_2465",
     label: "קורס מתקדם",
   },
   ```
   ועדכן את הטיפוס `FormKey` ואת `fixedInterest` ב-`LeadForm` שיכיר את
   המפתח החדש.
3. הטמע: `<LeadForm ... fixedInterest="advanced" />`.

## 3. מה השרת שולח ל-Scalla (החוזה המדויק)

מתוך `forwardToScalla()` ב-`route.ts`. כל הגשה שולחת:

| שדה ל-Scalla | מקור | הערה |
|---|---|---|
| `publicid` | לפי הדף | מזהה הטופס — קבוע לכל מוצר |
| `name` | לפי הדף | **שם הטופס המדויק** — חייב להתאים אחרת נדחה |
| `firstname` / `lastname` | המשתמש | |
| `email` / `mobile` | המשתמש | |
| `cf_2465` | קבוע `"כן"` | אישור דיוור — **שדה חובה בטפסים** |
| `cf_2662` | *(כבוי)* | סוג ליד — לא מוגדר בטפסים כרגע, ולכן לא נשלח |
| `__vtrftk` | env, אופציונלי | Scalla לא דורשת אותו בפועל |
| **שדה חותמת-זמן** | env `SCALLA_LAST_INQUIRY_FIELD` | ראה §4 |

## 4. שדה חותמת-הזמן — הפתרון ל"ליד חוזר"

**הבעיה:** Scalla מזהה כפילות לפי טלפון. ליד קיים שחוזר ושולח שוב את אותם
פרטים → שום שדה לא משתנה → אף טריגר (התראה / WhatsApp) לא נורה. הפנייה
"נבלעת" למרות שהאדם פנה באמת.

**הפתרון:** בכל הגשה השרת כותב לשדה אחד ערך ש**תמיד משתנה**, כי הוא מכיל
חותמת זמן:
```
ייעוץ לעסקה · 24-08-2026 18:45
```
- ליד חדש → השדה מתמלא.
- ליד חוזר → השעה **משתנה** → הטריגר נורה.
- בונוס: הערך גם מציג את **סוג הליד**, כך שלידים זהים־למראה נבדלים ב-CRM.

**חצי מהפתרון בצד Scalla (חובה, לא בקוד):**
1. צור שדה טקסט חדש במודול "לידים" (למשל "פנייה אחרונה").
2. מַפֶּה אותו בשני ה-Webforms.
3. שים את מזהה השדה (`cf_XXXX`) במשתנה הסביבה `SCALLA_LAST_INQUIRY_FIELD`
   ב-Vercel (או כברירת מחדל בקוד).
4. הגדר ב-Scalla **טריגר**: "כשהשדה הזה משתנה → שלח WhatsApp ללקוד + התראה לצוות".

> ⚠️ עד שהשדה קיים ומוגדר ב-`SCALLA_LAST_INQUIRY_FIELD` — הקוד פשוט מדלג
> עליו (no-op). הוא לא שובר כלום, פשוט לא פעיל.

> ⚠️ **הנחה לא מאומתת:** כל זה עובד רק אם Scalla **מעדכנת** את הרשומה
> הקיימת בהגשה חוזרת (ולא זורקת אותה). צריך לוודא בהגדרת "מניעת כפילויות"
> של Scalla שההעדפה היא לעדכן/לשמור את החדש, לא לחסום.

## 5. הגדרות Scalla שצריך לוודא (לא בקוד)

אלה חיים בממשק Scalla ואינם בשליטת הקוד:

1. **מניעת כפילויות** (מודול לידים → הגדרות → מניעת כפילויות): להחליט אם
   לאפשר כפילויות, או למזג/לעדכן. **אם חוסמים לגמרי — לידים חוזרים נבלעים.**
2. **שדה חותמת-הזמן + טריגר** — ראה §4.
3. **התראה על ליד/עדכון** — במיוחד לייעוץ (הכי דחוף).
4. **שמות הטפסים** חייבים להישאר בדיוק: `טופס לימודים`, `טופס ייעוץ או לימודים`.
   אם משנים שם ב-Scalla — צריך לעדכן את `formName` בקוד.

---

## 6. משתני סביבה (ב-Vercel)

הכל אופציונלי — ה-publicid ושמות הטפסים כבר קבועים כברירת מחדל בקוד.
הוסף רק את מה שצריך:

| משתנה | מתי צריך |
|---|---|
| `SCALLA_LAST_INQUIRY_FIELD` | כדי להפעיל את שדה חותמת-הזמן (§4) — **מומלץ** |
| `SCALLA_*_VTRFTK` | רק אם Scalla תתחיל לדרוש טוקן (כרגע לא) |
| `SCALLA_*_PUBLIC_ID`, `SCALLA_*_FORM_NAME` | לעקוף את ברירות המחדל בקוד |
| `SCALLA_*_LABEL` | לשנות את הטקסט בשדה חותמת-הזמן |

הרשימה המלאה מתועדת ב-`.env.example`.

## 7. איך לבדוק שהכל עובד (אחרי כל שינוי)

1. שלח ליד מכל דף — עם **אימייל וטלפון ייחודיים** (כדי לנטרל כפילות).
2. ודא הודעת "תודה! קיבלנו את הפנייה" (ירוקה) — סימן ש-Scalla אישרה.
3. בדוק ב-Scalla שהרשומה נוצרה, עם השדות והסוג הנכונים.
4. אם משהו נדחה — הסיבה המדויקת נרשמת ב-Vercel Logs תחת
   `[lead] Scalla rejected lead:`.

> טיפ מהניסיון: לבדיקת "ליד חוזר", שלח פעמיים עם **אותו** טלפון וראה אם
> הרשומה הקיימת מתעדכנת. זה מאמת את התנהגות מניעת-הכפילויות של Scalla.
